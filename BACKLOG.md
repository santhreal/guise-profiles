# BACKLOG - guise-profiles

Seeded 2026-07-17 (Claude manual audit). Pure reference-data crate: per-persona browser identity (UA, headers, client hints, hardware) plus the transport-layer TCP/IP SYN fingerprint projection (os_network). os_network.rs is exceptionally hardened (fail-closed JA4T, advisory-vs-assertable field discipline, Tier-B olayout in the sibling guise crate); findings are the residual duplication, a latent panic on the hardware tables, and the Tier-B generalization gap for the compiled-in persona tables. src/os_network.rs:84-87 + :129-132 | one-place | low | Claude 2026-07-17: the TCP advertised-window field is rendered by a byte-identical 4-line match block in BOTH p0f_signature (84-87) and ja4t (129-132): `match self.tcp_window { MssScaled => "*".to_string(), Fixed(v) => v.to_string() }`. Two owners for one rendering rule — if the `*`/fixed convention ever changes (e.g. a different wildcard marker) a maintainer must edit both and byte-identical copies drift. | Extract one `fn window_field(&self) -> String` (or `Cow<str>`) on OsNetworkStack and call it from both methods. Behavior-identical; single owner. Lock with a test asserting both signatures render the same window token for the same stack.
src/lib.rs:1028-1036 | robustness,panic | medium | Claude 2026-07-17: profile_hardware indexes `profile_hardware_variants(profile)[0]` (1029) and profile_hardware_at does `variants[index % variants.len()]` (1036). Both are runtime-callable const fns with NO guarantee that a per-profile hardware table is non-empty: an empty table makes profile_hardware panic (index out of bounds) and profile_hardware_at panic (`% 0` divide-by-zero). The safety rests entirely on every hardcoded *_HARDWARE static currently having >=1 entry; adding a new StealthProfile with an empty table, or emptying an existing one, is a latent runtime panic with no compile-time signal — inconsistent with the crate's own fail-closed-at-compile-time discipline (profile_os_network_stack uses a const panic deliberately). | Guarantee non-emptiness at compile time: add a `const { assert!(!TABLE.is_empty()) }` per hardware table (or a single generic check over profile_hardware_variants for every StealthProfile), so an empty table is a compile error. Proving test: an exhaustive test asserting profile_hardware and profile_hardware_at(_, 0) succeed for every StealthProfile variant.
src/lib.rs (persona reference tables, ~1000+ LOC) | generalization,tier-b | medium | Claude 2026-07-17: the crate bakes its entire persona fingerprint corpus — UA strings, header orders, client-hint brands, and the *_HARDWARE tables (CHROME_WINDOWS_HARDWARE, SAFARI_IPHONE_HARDWARE, ...) — as compiled-in Rust static arrays. These are precisely Tier-B data (fingerprint signatures/reference tables) that the Two-tier TOML doctrine says must live in TOML/data files under rules/, droppable to extend, NOT hardcoded (hardcoded lists are banned unless generated from Tier B). The sibling guise crate already proves the pattern is feasible: guise/src/fingerprint/os_network_tier_b.rs loads the TCP options layout from Tier-B data. So the crate is internally inconsistent — one fingerprint dimension (olayout) is Tier-B-loadable while the far larger persona tables are frozen in source, meaning a user cannot add a new persona/hardware profile without recompiling. | Move the persona/hardware/client-hint reference tables to Tier-B data files (rules/personas/*.toml) with a loader + validation, keeping the compiled tables only as an embedded default set generated from that same data (single source). A new persona becomes a dropped-in data file, not a source edit + recompile. This is a substantial refactor; stage it (schema -> loader -> migrate one table -> migrate the rest) and keep the embedded-default fast path.
